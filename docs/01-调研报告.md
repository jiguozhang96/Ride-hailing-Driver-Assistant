# 网约车跑单规划助手 —— 调研报告

> 调研范围：开源项目 / 市场竞品 / 技术方案选型（高德 API、限行规则、热力模型、算法）
> 调研方法：多子代理并行检索 + 交叉验证；关键结论标注来源与置信度（高/中/低）。
> 生成时间：2026-08-14

---

## 一、结论摘要（TL;DR）

1. **产品定位安全**：面向司机**自用**的行程规划工具不触碰合规红线；红线是「自动抢单 / 虚拟定位 / 接入平台私有接口」，本产品三者均不涉及（置信度：高）。
2. **技术路线可行**：纯前端 H5 + 高德 API + 本地存储即可完整交付，**无需后端服务器**；高德个人开发者即可申请（月配额制），无企业资质门槛（置信度：高）。
3. **核心差异化**：竞品（滴滴司机端等）已有"热力图/听单推荐"，但存在**热力图滞后、司机扎堆**两大痛点；本产品的差异化是「**提前 30-60 分钟的供需缺口预判 + 反扎堆路线轮换**」（置信度：中）。
4. **数据短板已规避**：真实打车订单热力不对个人开放，采用「**规则引擎 + 公开 POI/班次常识**」构建热力模型，可调参、可后续接入真实数据源（置信度：高）。

## 三、市场竞品分析

| 竞品 | 已有能力 | 司机痛点（公开反馈归纳） | 置信度 |
|---|---|---|---|
| 滴滴司机端 | 未来热力预测、无单保障推荐路线 | 热力图滞后、热门区扎堆 | 中 |
| 高德打车司机端 | 热力图层 | 需求热度与实际派单量不完全一致 | 中 |
| 美团打车司机端 | **每周接单战报** | 形态与本产品「周度规划」最接近 | 中 |
| T3 / 享道 / 曹操 | 热力图 + 调度建议 | 数据黑盒、司机缺乏主动规划工具 | 低 |

**结论**：各平台司机的"推荐"本质是**平台调度利益的延伸**（引导司机去平台需要的地方），而非**司机收益最大化**。本产品站在司机视角做独立规划，是明确的差异化定位（置信度：中）。

### 5.3 路径规划算法选型

在纯前端 JS 环境下，采用：
**热力评分（0-10）→ 时间窗分段（2h）→ 贪心选择（距离惩罚 + 连续停留递减）→ 续航约束（充电/加油插入）→ 饭点补给 → 回程收车**

- 距离惩罚：每公里空驶扣 0.35 分；连续停留第 2 窗口起扣 1.8 分（鼓励轮换热点，反扎堆）。
- 运营里程估算：市区运营时速 18km/h × 时长（更贴近真实一天 200-350km）。
- 候选点位 ≤5 时退化为直线距离贪心；距离矩阵调用节流 + 缓存。

## 六、合规边界（必须守住的三条红线）

1. **不接入任何平台的私有接口/协议**；
2. **不做自动抢单**；
3. **不做虚拟定位**。

以上行为已有刑事判例（《刑法》第 285 条非法侵入计算机信息系统等）。本产品定位为「司机自用的行程规划工具」，仅基于公开信息与司机自身输入做建议，**完全合规**（置信度：高）。

## 七、对产品设计的 8 条关键启示

1. 做「供需缺口预判」而非「历史热力图」（提前 30-60 分钟）。
2. 做「反扎堆路线轮换」，避免司机都涌向同一热点。
3. 周度规划要体现**单双休差异**（互联网大厂大小周）。
4. 枢纽（机场/高铁）是稳定收益来源，应作为骨架节点。
5. 续航约束是新能源司机的刚需，充电停留必须纳入规划。
6. 饭点补给（司机餐厅带）是现实需求，能提升工具「懂行」感。
7. 限行规则必须准确（外地绿牌不豁免这一细节决定了外牌司机可用性）。
8. 本地存储 + 无后端，让司机零门槛使用、数据零隐私风险。

# 网约车跑单规划助手 —— 产品设计方案

> 版本：v1.0 · 2026-08-14 · 示例城市：上海
> 定位：司机自用的行程规划工具（纯前端 H5，本地存储，高德 API 可选集成）

---

## 一、产品概述

### 1.1 一句话定位
帮出租车/网约车司机在**出车前**快速生成一份「今天去哪跑、几点去、顺不顺路、要不要充电」的日度/周度路线规划，替代凭经验瞎转。

### 1.2 目标用户与核心痛点

| 痛点 | 现状 | 本产品解法 |
|---|---|---|
| 不知道去哪等单 | 凭经验/跟风扎堆 | 按时段热力推荐 + 反扎堆轮换 |
| 新能源怕没电 | 自己算续航 | 续航约束 + 充电站停留规划 |
| 限行被罚 | 记不住规则 | 按车牌自动判定 + 规避提示 |
| 吃饭没着落 | 随机找地方 | 司机餐饮带补给节点 |
| 不懂单双休规律 | 周一/周六乱跑 | 周度规划体现大小周差异 |

### 1.3 差异化
- 竞品推荐 = 平台调度利益延伸；本产品 = **司机收益视角**独立规划。
- 「供需缺口预判 + 反扎堆」而非「滞后热力图」。

## 二、用户旅程（核心工作流）

```
司机打开 H5
  → 填写档案（城市/住宿/车型/车牌/续航/出车收车/跨城/大周/天气）
  → 点击「生成跑单规划」
  → 查看日度规划表（时间→点位→热力→策略→里程）
  → 查看路径示意图（SVG 离线 / 高德在线）
  → 查看周度规划（7 天节奏）
  → 复制文字版 / 导出 CSV / 跳转导航
  → 数据自动保存在本机，下次打开直接复用
```

## 四、核心设计：热力模型（规则引擎）

### 4.1 点位分类
| 类型 | 含义 | 典型点位（上海） |
|---|---|---|
| biz | 办公商务区 | 陆家嘴、静安寺、漕河泾、张江、前滩 |
| hub | 交通枢纽 | 虹桥枢纽、浦东机场、上海站、上海南站 |
| night | 夜生活区 | 新天地、外滩、巨鹿路158、武定路 |
| shop | 商圈 | 人民广场、徐家汇、五角场、中山公园 |
| home | 大型居住区 | 莘庄、金桥、共富/顾村、真如 |
| edu | 高校区 | 松江大学城 |
| meal | 司机餐饮带 | 崂山路、真北路（补给节点，非跑单目标） |

### 4.2 热力计算公式
```
热力分(zone, 星期类型, 小时, 天气) =
  基础模板[类型][小时] × 星期修正[星期类型][类型] × 天气系数
```
- 星期类型：工作日 / 周五 / 周六 / 大周周六(上班) / 周日 / 节假日。
- 天气系数：晴 1.0 / 多云 1.0 / 小雨 1.25 / 暴雨 1.5 / 雪 1.4 / 极端 0.6。

### 4.3 时段规律（上海经验，可调参）
| 时段 | 规律 | 推荐类型 |
|---|---|---|
| 7:00-9:00 早高峰 | 居住区→办公区出发潮 | home（上车）+ biz（下车短驳） |
| 9:00-17:00 平峰 | 枢纽到达 + 商圈 | hub + shop |
| 17:00-20:00 晚高峰 | 办公区出发潮 | biz |
| 21:00-23:30 加班潮 | 互联网园区下班 | biz_overtime（漕河泾/张江） |
| 22:00-02:00 夜生活 | 酒吧/夜店回程 | night |
| 周五晚 | 夜生活翻倍 + 跨城返乡 | night + hub |
| 周六 | 商圈全天高热，办公冷 | shop |
| 周日 | 返程/返校潮 | hub + edu |

### 4.4 热力星级（输出展示）
| 分值 | 星级 | 标签 |
|---|---|---|
| ≥8 | ★★★★★ | 爆单区 |
| 6.5-8 | ★★★★☆ | 高需求 |
| 5-6.5 | ★★★☆☆ | 稳定 |
| 3.5-5 | ★★☆☆☆ | 一般 |
| <3.5 | ★☆☆☆☆ | 偏冷 |

## 五、核心设计：日度规划算法

```
输入：档案(车型/车牌/续航/出车收车/跨城/大周) + 日期 + 天气
输出：分段跑单时间表 + 总里程 + 摘要

步骤：
1. 按 2h 把出车-收车时段切成时间窗
2. 每窗对候选点位打分：热力分 − 空驶距离×0.35 + 连续性奖励/惩罚 + 跨城枢纽加成
3. 贪心选最高分点位；连续停留≥2窗时扣 1.8 分（反扎堆）
4. 运营里程 = 时长 × 18km/h；累计接近 80% 续航 → 插入充电/加油
5. 饭点(11-13/17-19) → 推荐最近司机餐饮带
6. 收车 → 回住宿地路径
```

## 八、API 集成方案（降级设计）

高德集成采用 **JS API 2.0 插件体系**（key 类型为「Web端 JS API」+ 安全密钥 jscode），而非 REST 接口。

| 功能 | 有高德 key（JS API 2.0 插件） | 无 key（降级） |
|---|---|---|
| 地址→坐标 | `AMap.Geocoder` 地理编码 | 默认坐标/列表选 |
| 路径示意图 | `AMap.Map` 在线地图 + 点位标注 | **内置 SVG 示意图（离线可用）** |
| 充电/加油/餐饮 POI | `AMap.PlaceSearch` 周边搜索 | 内置餐饮带锚点 |
| 天气 | `AMap.Weather` 实时天气 → 热力档位 | 手动选择天气档位 |
| 驾车路线 | `AMap.Driving`（预留） | 高德 uri 导航跳转（无需 key） |
| 导航跳转 | `uri.amap.com` 唤起高德 App | 同左（无需 key） |

> **结论：只需 1 个「Web端（JS API）」key + jscode 即可解锁全部实时能力；不申请也可完整使用（离线 SVG）。**
> ⚠️ key 类型若误申请为「Web服务」，会报 `USERKEY_PLAT_NOMATCH`（10009）。详见《03-API-Key注册指引》。

## 九、技术栈与项目结构

```
app/
  index.html          单页入口
  css/main.css        移动端样式（手机优先）
  js/app.js           路由 + 视图渲染 + 事件
  js/storage.js       localStorage 封装
  js/amap.js          高德 API（可选）
  js/engine/
    poi-db.js         点位数据库
    heat-model.js     热力模型
    restrictions.js   限行规则
    planner.js        日度规划算法
    week-planner.js   周度规划
  js/ui/schematic.js  离线 SVG 示意图
```

- 无框架、无构建、无后端；ES Module 直接运行。
- 启动：任意静态服务器（如 `python -m http.server`）或部署到静态托管。
